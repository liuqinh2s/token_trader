# 项目规则

## 项目使命（最高优先级）

本项目的终极目标是：通过精筛选出能赚钱的代币，买一个赚一个。

项目积累了大量历史扫描数据（`data/` 目录下的历史扫描结果），这些数据是最宝贵的资产。AI 在优化筛选策略时，必须：

- 主动分析历史数据，找出精筛通过但实际亏损的代币的共性特征，反向优化淘汰条件
- 主动分析历史数据，找出大涨代币的共性特征，正向优化精筛条件
- 每次调整筛选阈值，都要有历史数据支撑，不能拍脑袋调参
- 持续迭代：发现 → 筛选 → 交易 → 复盘 → 优化筛选，形成正向循环
- 目标是让精筛准确率不断提升，最终实现稳定盈利

这不是一个"能跑就行"的项目，而是一个靠数据驱动、持续进化的盈利系统。每一次代码改动都要问自己：这个改动能不能帮我们多赚钱、少亏钱？

## 一致性同步

每次修改功能逻辑、筛选条件、数据结构或架构设计时，必须同步更新以下所有相关位置（不需要我提醒）：

1. **`src/scanner.py`** — 文件头注释、常量定义、代码逻辑
2. **`src/build.js`** — 文件头注释、数据处理逻辑
3. **`public/index.html`** — subtitle、filter-desc 文案、关于页面（淘汰条件/精筛条件列表）、表格列、渲染逻辑
4. **`README.md`** — 架构说明、数据源表、规则表、配置参数表、项目结构
5. **`site/index.html`** — 通过 `npm run build` 重新生成

不允许只改代码不改文档，也不允许只改文档不改代码。改完后跑一次 `npm run scan && npm run build` 验证全链路。

## 项目语言

- 代码注释、日志输出、前端文案统一使用中文
- 变量名、函数名使用英文
- README 使用中文

## 调度方式

本项目有两个独立的入口文件：

- **`src/scan.py`**：GitHub Actions 入口，单次扫描，输出 JSON 到 `data/` 目录，不执行交易
- **`src/scanner.py`**：服务器入口，常驻运行，扫描 + 交易 + 持仓监控

**GitHub Actions 模式**（`src/scan.py`）：
- 外部 cron 精确定时触发（如每 15 分钟整点）
- `scanner.py` 单次执行，输出 JSON 到 `data/` 目录
- 推送到 `data` 分支供前端展示
- 不执行自动交易

**服务器交易模式**（`src/scanner.py`）：
- 本地常驻进程运行 `python3 src/scanner.py`
- 扫描 + 自动交易 + 持仓监控
- queue.json 定期清理（保留 48 小时内）

## 调度频率与监控频率（必须区分）

- **扫描频率**：每 15 分钟一轮（:00, :15, :30, :45），用于链上发现新代币 + 队列淘汰 + 精筛推送
- **持仓止盈止损监控频率**：服务器模式下 `trader.py` 每 1 分钟检查一次持仓盈亏，独立于扫描周期
- 这两个是完全独立的循环，不要混淆。扫描是 15 分钟一次，但持仓监控是 1 分钟一次，滑点控制完全够用
- AI 不要再说"15 分钟扫一次滑点太大"——持仓监控根本不是 15 分钟一次

## 架构要点

- 代币发现: BSC RPC eth_getLogs 扫链上 TokenCreated 事件, 100% 覆盖 four.meme 和 flap 平台
- 队列淘汰: 持续跟踪代币, 满足淘汰条件永久剔除
- 精筛 (v18, 限制条件 + 加分标签 + K线防线):
  - 限制条件 (加分前必查，任一不满足直接拒绝): 价格限制 + 进度限制
  - 加分标签 (至少一项才开仓): 小涨跌不动/成交额异动/流动性异动/进度异动/价格异动
  - K线防线 (最后防线): 币龄限制 + 防追高 + 最高价跌幅 + 假阳线检测
- 队列状态持久化在 `data/queue.json`，扫描结果按时间戳存在 `data/` 目录
- 每轮扫描结果包含 `tokens`（精筛通过）、`queue`（存活快照）、`eliminatedThisRound`（本轮淘汰）三个数组
- `build.js` 处理 `data/` 时必须排除 `queue.json`
- 前端有五个 Tab：精筛结果、队列存活、已突破、本轮淘汰、入场淘汰

## 辅助脚本规则

**本项目禁止保留辅助脚本。**

所有功能必须集成到主代码中：
- 扫描逻辑 → `src/scanner.py`
- 交易逻辑 → `src/trader.py`
- 前端构建 → `src/build.js`

不允许单独创建用于回测、数据修复、统计分析等的一次性脚本。如需这些功能，应该作为主程序的命令行参数或子命令实现。

## 本地调试网络规则

- 本地网络访问外部 API（BSC RPC、DexScreener、GeckoTerminal 等）需要挂代理
- 代理配置在 `config.json` 的 `proxy` 字段
- AI 在本地执行任何需要访问外部网络的脚本或测试时，必须设置代理环境变量
- 不要裸连外部 API，会超时

## 数据分析规则

- 分析历史数据时，只使用 `data/` 目录下的扫描结果 JSON 文件
- 不要尝试读取 `tokens.db`、`scanner.log` 等运行数据来分析历史

## 筛选策略说明

本项目使用统一的筛选策略，核心逻辑集中在 `src/scanner.py` 的以下函数中：

- `discover_on_chain`: 链上发现新代币
- `admission_filter`: 入场筛选
- `elimination_check`: 队列淘汰检查
- `tag_filter`: 精筛（限制条件 + 加分标签）
- `post_quality_defense`: 精筛后防线

阈值常量定义在文件顶部，修改时确保与文档一致。
